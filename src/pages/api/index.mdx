## About the API

The Relaton API provides HTTP access to the same bibliographic data that the Ruby gems fetch locally. Given a document key (e.g., `RFC 8446`, `ISO 690:2021`), it returns the full Relaton bibliographic record — titles in every stored language, contributors, dates, identifiers, relations, and classifications.

The API is read-only and requires no authentication. Responses carry a strong
`ETag` with immutable caching semantics, so a repeated request with
`If-None-Match` answers `304 Not Modified`.

## One document

```
GET https://api.relaton.org/v3/documents/{key}
```

The key is the document's canonical identifier. Content negotiation picks the
serialization — via the `Accept` header, or an explicit `format` parameter:

| Representation | Accept / format | Notes |
|---|---|---|
| Relaton JSON | `application/json` (default) | The lossless model serialization |
| Relaton XML | `application/relaton+xml` or `format=xml` | Bibdata XML, streamed from storage |
| Relaton YAML | `application/yaml` or `format=yaml` | The model as YAML |

```bash
curl -s https://api.relaton.org/v3/documents/RFC%208446
curl -s -H 'Accept: application/relaton+xml' https://api.relaton.org/v3/documents/RFC%208446
```

Errors are RFC 9457 problem+json: `404` for an unknown key, `406` when XML is
negotiated but the document has no stored XML serialization.

## Search

```
GET https://api.relaton.org/v3/documents?q=…&flavor=…&year=…&limit=…&cursor=…
```

Results are key-ordered and cursor-paginated: the response carries
`next_cursor`, and the `Link` header holds `rel="next"` when more pages
remain. Filters: `q` (title text), `flavor`, `year`, `doctype`, `status`.

## Supported Organizations

The API supports all 28 Relaton flavors — 26 standards organizations plus DOI and ISBN identifier systems:

ISO, IEC, IETF, ITU (T/D/R), NIST, BIPM, 3GPP, IEEE, W3C, CalConnect, OGC, IHO, OASIS, CIE, OMG, UN, GB, CCSDS, IANA, XSF, IEV, DOI, ISBN, and more.

For the full list with data sources, see the [Flavors page](/flavors/); live
coverage (per-flavor document counts and index timestamps) is at
[api.relaton.org/v3/flavors](https://api.relaton.org/v3/flavors).

## OpenAPI and GraphQL

The interface is specified in two complementary ways:

- **OpenAPI 3.1** — machine-readable spec at [api.relaton.org/openapi.json](https://api.relaton.org/openapi.json), interactive reference at [api.relaton.org/docs](https://api.relaton.org/docs).
- **GraphQL** — the schema mirrors the [Relaton model](/model/): a
  `BibliographicItem` with every docid, title (all languages), date,
  contributor, relation, and classification. Search across *all* flavors at
  once at [api.relaton.org/graphql](https://api.relaton.org/graphql)
  (GraphiQL playground included):

```bash
curl -s https://api.relaton.org/graphql \
  -H 'Content-Type: application/json' \
  -d '{"query":"{ documents(title: \"risk assessment\", first: 5) { edges { node { key flavor docids { content } titles { content language } } } } }"}'
```

Relations traverse across flavors: `relations { type target item { key } }`
resolves the related document, and `documents(relation: { type: "updates" })`
filters by relation.

## Rate Limits

The API is provided as a public service for standards development. Please use responsibly — cache results locally when possible (the immutable `Cache-Control` responses are designed for it), and avoid bulk queries in tight loops.
